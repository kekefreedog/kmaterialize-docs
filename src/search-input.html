Customize the field

These controls reinitialize the same Kmaterialize input. Leave an icon name empty to hide it.

Setup

{{> input-setup-note }}

Initialize a native input with SearchInput.init(). The component creates its pill, icons, clear action and accessible status message. Keep an accessible label on the input; no additional peer dependency is needed.

<input id="artist-search" type="search" data-search-input
    class="no-autoinit" placeholder="Find an artist…"
    aria-label="Filter artists" autocomplete="off">
import { SearchInput } from "kmaterialize";
import "kmaterialize/dist/css/materialize.css";

// Read application records to filter
const records = [...document.querySelectorAll("[data-search-record]")];

// Initialize the reusable field
const search = SearchInput.init(document.querySelector("#artist-search"), {
    icon: "person_search",
    iconRight: "filter_alt",
    clearable: true,
    matchSingular: "artist",
    matchPlural: "artists",
    getMatches(query) {
        // Prepare result
        let result = 0;

        // Filter the application's records
        for(const record of records){
            // Compare the displayed name
            const matches = record.textContent.toLowerCase().includes(query.toLowerCase());

            // Update this application's list
            record.hidden = !matches;

            // Count visible records
            if(matches){
                // Include this match
                result++;
            }
        }

        // Return result
        return result;
    }
});

getMatches(query, instance) receives the trimmed query on initialization, editing, clearing and refresh. Return a non-negative integer, or null to hide feedback. Filtering or highlighting belongs to your callback, so the same input can control a list, spreadsheet or seating plan.

For automatic initialization, remove no-autoinit and call M.AutoInit(container, { SearchInput: options }). It recognizes input[data-search-input] and legacy input.toolbar-search-input, excluding no-autoinit. Plain scripts use M.SearchInput.

HTML options and full-width columns

Set icons, labels and toggles directly on the input with data-search-*. The library reads them during SearchInput.init() or M.AutoInit(). Explicit JavaScript options override HTML values, which override defaults. Reinitialize after changing configuration attributes.

This example uses col s12 and fills the column automatically. Kmaterialize’s grid only needs s12; the extra col class is optional. Responsive classes also work directly on the input: the generated wrapper inherits its grid classes, such as s12 m6.

  • Ada Martin · Lighting
  • Alex Chen · Animation
  • Sam Rivera · Lighting
<div class="row">
    <div class="s12">
        <input id="artist-filter" type="search" data-search-input
            data-search-icon="person_search"
            data-search-icon-right="filter_alt"
            data-search-clear-icon="backspace"
            data-search-clear-label="Clear artist search"
            data-search-clearable="true"
            data-search-show-matches="true"
            data-search-match-singular="artist"
            data-search-match-plural="artists"
            placeholder="Find an artist…" aria-label="Filter artists">
    </div>
</div>

Use data-search-clearable="false" to hide the clear button and data-search-show-matches="false" to hide the counter. A bare boolean attribute or "true" enables the option; "false" disables it. Empty data-search-icon="" or data-search-icon-right="" omits that icon. placeholder, value and aria-label remain native input attributes.

Outside a grid column, use data-search-full-width (or fullWidth: true) to fill the parent. Otherwise the field keeps its compact 380px default. Grid columns always use their available width; --search-input-width can override it explicitly.

<input type="search" data-search-input data-search-full-width
    placeholder="Search…" aria-label="Search">

Functions stay in JavaScript: pass getMatches, formatMatches and onError through initialization. HTML attributes configure presentation; they do not execute function names or code.

// Read HTML presentation settings and supply application matching
M.AutoInit(document.body, {
    SearchInput: {
        getMatches: query => countArtists(query)
    }
});

Toolbar item

Place the same input directly in a toolbar or a toolbar-group. It stays visible, with a compact height. This example uses a right icon and artist / artists labels.

  • Ada Martin · Lighting
  • Alex Chen · Animation
  • Sam Rivera · Lighting
<div class="toolbar">
    <div class="toolbar-group">
        <input type="search" data-search-input class="no-autoinit"
            aria-label="Filter artists" placeholder="Find an artist…">
    </div>
</div>

Initialize it with the same SearchInput.init() options, or let Toolbar.init() initialize it. Add data-search-expandable to start as an accessible icon button; the toolbar page demonstrates expandable, customized, full-width and prefilled examples using this same component.

<input type="search" data-search-input data-search-expandable
    data-search-icon="person_search"
    data-search-expand-label="Open artist search"
    aria-label="Filter artists" placeholder="Find an artist…">

Expandable fields open on button activation or native input focus, remain expanded while a query is present, and collapse when an empty field loses focus. Escape clears and collapses back to the opener. The clear button keeps the field open. If the leading icon is omitted, the opener uses search. Expansion respects disabled and readonly state and reduced-motion preferences.

Async results and custom text

The callback can return a promise. Only the latest returned count is displayed; clearing immediately removes old feedback. Supply onError to present or log failures. If your callback also renders remote records, manage those updates against the current query in your application.

// Initialize remote matching with a complete count formatter
SearchInput.init(input, {
    icon: null,
    iconRight: "person_search",
    clearable: false,
    getMatches: query => countArtists(query), // Promise<number | null>
    formatMatches: count => `${count} ${count === 1 ? "résultat" : "résultats"}`,
    onError: error => console.error("Could not count artists", error)
});

formatMatches(count, query, instance) overrides the whole counter, including the number. Text is inserted as plain text. An empty query always hides the counter, while still invoking getMatches("") so your application can reset filtering.

Method / propertyPurpose

Clear keeps focus in the input. Escape returns focus to the opener in expandable mode, or retains input focus in always-open mode. Native form reset, disabled fieldsets, readonly values and IME composition are supported. Counts use a polite live region and preserve existing aria-describedby help text.

Presentation options map to their kebab-case HTML attributes: iconRight becomes data-search-icon-right, clearLabel becomes data-search-clear-label, and so on. All icons, labels and boolean options above support this form.

Set --search-input-width and --search-input-height on a parent to adjust sizing. Width defaults to 380px with a 100% maximum outside grid columns; columns and fullWidth use 100%. Height is 40px standalone and 34px inside a toolbar. Colors follow the active Material theme.
